# Networks

Test networks for LeanBatfish. Each folder is a Batfish snapshot: device configurations in
`configs/`, and any other inputs Batfish reads (host files, external BGP announcements)
beside it. They serve two purposes: differential tests against Batfish, and concrete
networks to state and prove properties about. Each folder also holds Batfish's export of
the snapshot (`export/`: its vendor-independent model, adjacencies and answers, written by
`tools/export.py`) and the network's Lean modules: `Model.lean`, its model, generated by
`tools/model.py`, which reads `export/`; and `Properties.lean`, properties proved about it
(for `example`, `ipsec-vpn` and `ipsec-negotiation`). `ipsec-vpn` also has a picture of the
network and of what is proved, `diagram.pdf`. `tools/export.py` leaves `export/`, the Lean
modules and PDFs out when it gives the snapshot to Batfish. All networks except
`conditional-export` (which uses tracking) are inside the modeled subset, and the
simulator's answers match Batfish's on every one.

Most come from Batfish's own examples, tutorials and tests (Apache License 2.0), copied
unchanged:

| Network | Source | What it exercises |
|---|---|---|
| `example` | `batfish/networks/example/live` | Batfish's example network: three ASes of Cisco IOS routers with eBGP, iBGP, OSPF, communities, BGP aggregation, and two hosts |
| `example-bgp` | pybatfish notebook *Introduction to BGP Analysis* | a variant of `example` used to study BGP sessions and policies |
| `route-analysis` | pybatfish notebook *Introduction to Route Analysis* | two Cisco border routers with prefix lists, AS-path access lists and communities |
| `rrrc` | Batfish test `dataplane/ibdp/route-reflection/rrrc` | route reflection across Cisco and Juniper, with external BGP announcements |
| `multipath-multiple-as` | Batfish test `grammar/juniper/testrigs/multipath-multiple-as` | Junos BGP multipath across different neighbor ASes |
| `conditional-export` | Batfish test `grammar/juniper/testrigs/conditional-export` | Junos policies that export a route only while another route exists |
| `example-candidate` | `batfish/networks/example/candidate` | a proposed change to `example` |
| `example-announcements` | `batfish/networks/example/live-with-bgp-announcements` | `example` with BGP announcements from outside the network |
| `failure-analysis` | pybatfish notebook *Analyzing the Impact of Failures* | a Cisco network of thirteen cities with BGP and OSPF |
| `forwarding-change-base`, `forwarding-change-1` | pybatfish notebook *Introduction to Forwarding Change Validation* | a data-center network before and after a change |
| `drift-reference`, `drift-snapshot` | pybatfish notebook *Uncovering Configuration and Behavior Drift* | two versions of the example network that drifted apart |

Two were written for this repository, to study IPsec:

| Network | What it exercises |
|---|---|
| `ipsec-vpn` | two sites (A: `a1`, `a2`, gateway `gwa`; C: `c1`, gateway `gwc`) joined by a route-based IPsec tunnel (Cisco IOS VTI, ESP with AES-256) across a provider B (`b1`, `b2`, OSPF) |
| `ipsec-negotiation` | a hub with seven spokes, one per outcome of IPsec negotiation: established route-based (Cisco and Junos `st0`) and policy-based (crypto map) sessions, a key mismatch, a phase-1 and a phase-2 mismatch, a dynamic crypto map, and a tunnel to a peer that does not exist |

The Batfish sources are from commit `3af8938` of the Batfish repository; the notebooks
are the ones shipped in the `batfish/allinone:test-2026.10.22.3852` image.

To export Batfish's view of all of them again (with Batfish running, see the main README):

```sh
.venv/bin/python tools/export.py --discover networks
.venv/bin/python tools/model.py          # regenerate the models
lake build                               # check the models and properties
```
